# political-compass-quiz — 정치성향 진단 설계

5축 `AxisVector`를 산출하는 설문을 `data-contract.md` 2절 `quiz.json` 형식으로 만든다.

## 왜 이렇게 하나
사용자와 후보를 같은 5축에서 비교하려면, 설문이 그 5축을 **균형 있고 편향 없이** 측정해야 한다. 채점은 결정적이어야 검증·재현이 가능하고, 경계 응답이 ±100에 정확히 닿아야 레이더·일치도가 직관적이다.

## 설계 규칙
- **분포**: 5축 × 각 3~4문항 = 16~20문항. 축 간 균형.
- **문항**: 한 문장 진술형, 5점 리커트(매우동의 +2 … 매우반대 -2). 유도·이중질문·특정 정당/인물 금지.
- **부호 규약**: 각 문항에 `axis`와 `direction`(+1/-1). 동의가 +축인지 -축인지 명확히. policy-axis-scoring의 축 부호와 일치.
- **한국 지방선거 맥락**: 지역개발 vs 환경보전, 복지확대 vs 재정건전성, 부동산·임대, 교육(교육감), 대북, 치안, 공공 vs 민간 등에서 축별로 고르게.

## 채점식 (결정적)
1. 문항 응답 score ∈ {-2,-1,0,1,2}.
2. 축별 원점수 raw = Σ(score × weight × direction).
3. 정규화: `axisScore = round( raw / maxRaw × 100 )`, `maxRaw = Σ(2 × weight)`(해당 축 문항). → -100..100, 경계 응답이 ±100.
4. 결과 `AxisVector` 5개 값.

## 워크플로우
1. 축별 문항 초안 → direction·weight 지정.
2. 경계 케이스 검산표 작성: 전부 +2 / 전부 -2 / 전부 0 / 혼합 → 각 축 점수 계산해 ±100·0 확인.
3. 편향 점검: 문항이 한 정당 입장을 "정답"처럼 보이지 않는지.
4. 모바일 표현 확인: 문항이 한 화면에 들어오는 길이인지.

## 산출
`_workspace/03_quiz_quiz.json`(계약 형식), `03_quiz_report.md`(분포·검산표).

## 흔한 함정
- 한 축에 문항 몰림 → 그 축만 과민. 분포 점검.
- direction 실수로 부호 반전 → 진보/보수 뒤집힘. 검산표로 잡는다.
- 정규화 상수 오류로 ±100 초과 → weight·maxRaw 재확인.
- 이중질문("A이고 B다") → 한 축만 측정하도록 분리.
