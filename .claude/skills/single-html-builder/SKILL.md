# single-html-builder — 모바일 퍼스트 단일 HTML

GitHub Pages에 그대로 올려 동작하는 **단일 HTML**을 만든다. 백엔드 없이 설문→성향→주소→후보 매칭→일치도까지 클라이언트에서 완결.

## 왜 이렇게 하나
배포를 쉽게(파일 하나 push) 하고 의존·장애 지점을 줄이려고 단일 파일로 굳힌다. 모든 계산이 클라이언트에서 끝나야 사용자 주소·응답이 서버로 새지 않아 프라이버시도 지킨다.

## 구조 (한 파일 인라인)
- `<style>` 인라인 CSS(모바일 퍼스트, CSS 변수 테마).
- `<script type="application/json" id="appdata">` 에 quiz/candidates/parties/districts 임베드(또는 `data.json` 동봉 fetch — 단일성 우선시 인라인).
- `<script>` 인라인 앱 로직.
- 외부 의존: Kakao 우편번호 서비스 스크립트만 권장. 차트는 **직접 그린 인라인 SVG 레이더**(CDN 불필요). 부득이 CDN 사용 시 주석으로 이유 명시.

## 화면 흐름 (모바일 퍼스트)
1. **인트로**: 선거 안내(제9회, 2026-06-03), 소요시간, 프라이버시 고지("모든 계산은 기기 안에서").
2. **설문**: 한 문항씩, 진행바, 5점 리커트 큰 터치 버튼. 이전/다음.
3. **성향 결과**: 5축 레이더(사용자), 축별 한 줄 해설.
4. **주소 입력**: Kakao 우편번호 → sido/sigungu/bname으로 `districts` 조회 → 사용자의 모든 선거 선거구 확정.
5. **후보 매칭**: 선거별(시도지사·교육감·구청장·시도의원·구의원…) 카드. 각 후보 일치도%(내림차순), 레이더 오버레이(나 vs 후보), 일치/불일치 축 Top, 기호·정당·사진(없으면 이니셜), 공약 요약(의원은 "정당 성향 기반" 배지).
6. **요약(투표장에서 이렇게)**: 선거별 최고 일치 후보 1인 + 한 줄 이유. "참고용" 고지.

## 매칭 로직 (data-contract 6절 그대로)
- 일치도 = `round((1 - dist/maxDist) × 100)`, `dist = sqrt(Σ(u_k - c_k)²)`, `maxDist = sqrt(5 × 200²)`.
- 근거: |u_k - c_k| 가장 작은 축=일치, 가장 큰 축=불일치로 2~3개 표기.

## 견고성
- 옵셔널 체이닝·기본값으로 누락 필드 방어. 데이터 없으면 UI에서 숨기고 console.warn.
- 사진 onerror → 이니셜 아바타. Kakao 스크립트 실패 → 수동 시도 선택 폴백.
- 의원 선거구 미해결 → 그 선거 카드에 "선거구 확인 필요" 안내, 단체장·교육감은 정상 노출.

## 프라이버시·중립 고지
- 외부 전송 코드 금지(주소·응답). 분석 스크립트 넣지 않음.
- "공약 기반 추정, 참고용" 문구와 출처(선관위 data.go.kr) 명시.

## 산출
`index.html`(최종), `_workspace/04_frontend_notes.md`(구현 결정·외부 의존·소비 필드 목록 — QA 경계면 대조용).

## 흔한 함정
- 데이터 필드명 임의 변경 → QA 경계면 깨짐. `data-contract.md` 필드만 사용.
- 레이더 좌표 계산 시 축 순서 불일치 → 사용자/후보 같은 축 순서로 매핑.
- 거대한 인라인 데이터로 파일 과대 → 필요시 `data.json` 분리(단, 같은 레포 동봉).
