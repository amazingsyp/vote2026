# nec-data-pipeline — 선관위 데이터 수집·정규화

data.go.kr 선관위 OpenAPI로 전국 후보·공약·선거구 데이터를 모아 `data-contract.md` 스키마의 JSON으로 만든다.

## 왜 이렇게 하나
정적 사이트(GitHub Pages)는 런타임에 인증 API를 호출할 수 없다(키 노출·CORS). 그래서 **빌드 시점에 한 번 수집해 JSON으로 굳혀** HTML에 임베드한다. 수집은 결정적·재현 가능해야 갱신과 검증이 쉽다.

## 데이터 소스
| 데이터 | data.go.kr | 비고 |
|--------|-----------|------|
| 선거공약 정보 | 15040587 | 시도지사·구시군장·교육감만 공약 제출 |
| 후보자 정보 | 15000908 | 이름·기호·정당·사진URL |
| 당선인(참고) | 15000864 | 선거 후 검증용 |

서비스 키는 사용자가 data.go.kr에서 발급(무료, 개발계정 1만건/일). 키는 **스크립트 인자/환경변수**로 받고 코드·산출물에 하드코딩하지 않는다.

## 워크플로우
1. **API 문서 확인**: 각 API의 요청 파라미터(sgId 선거ID, sgTypecode 선거종류, 페이지)와 응답 필드를 문서로 확인. sgTypecode 값을 추측하지 말고 검증(3 시도지사/4 구시군장/5 시도의원/6 구시군의원/7·8 비례/11 교육감).
2. **후보자 수집**: 모든 선거×선거구 페이지네이션 순회. 기호·정당·사진URL 포함.
3. **공약 수집**: 단체장·교육감 후보의 공약(제목·내용)을 후보ID로 조인. 의원은 건너뛰고 `pledges:[]`.
4. **정당 명단 추출**: 후보에서 정당 distinct 추출(성향 점수는 policy-analyst가 채움).
5. **선거구 매핑 구축**: 읍면동(행정구역)→각 선거 선거구 코드 표. 단체장·교육감은 시도/시군구로 결정(쉬움). 의원 선거구는 선관위 선거구획정 자료 필요(어려움 — 미해결은 null + 누락 목록).
6. **정규화·검증**: `data-contract.md` shape으로 변환, 필수 필드 누락·중복 id 검사, 선거별 카운트 로그.

## 산출
`_workspace/01_data_candidates.json`, `01_data_parties.json`, `01_data_districts.json`, `01_data_report.md`(통계+누락목록).

## 스크립트
반복 수집은 `scripts/fetch_nec.py`로 실행(키를 인자로). 페이지네이션·재시도·레이트리밋·정규화를 담는다. 최초 1회 작성 후 재사용·증분 갱신.

## 흔한 함정
- **공약 미제출 선거 오인**: 의원에 공약을 기대하지 말 것. `axisSource:"party"`로 넘긴다.
- **사진 URL 만료/핫링크 차단**: 깨지면 `null`로 두고 프론트가 이니셜 아바타 처리.
- **인코딩**: 선관위 응답이 EUC-KR일 수 있음 — UTF-8로 정규화.
- **선거구 코드 체계 혼선**: 행정구역코드 ≠ 선거구코드. 매핑표를 별도 관리.
- **키 미발급 상황**: 즉시 리더에게 보고하고 샘플 모드(대표 3~4개 시도 목업) 폴백 제안.
